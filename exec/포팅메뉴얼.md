## 3. 인프라 구축

### 3.1. 네트워크 구성 (Docker Network)

서비스 간의 격리 및 보안을 위해 용도별로 3개의 Docker 네트워크를 생성하여 운영합니다.

- **app-network**: Jenkins, Portainer 등 관리 도구 전용 네트워크.
- **dev-net**: 개발(Dev) 환경의 DB, Backend, Frontend가 통신하는 망.
- **prod-net**: 운영(Prod) 환경의 DB, Backend, Frontend가 통신하는 망.

```bash
docker network create app-network
docker network create dev-net
docker network create prod-net
```

### 3.4. Main Gateway (Nginx) & 관리 도구

외부 트래픽의 진입점(Gateway) 역할을 수행하며, Jenkins가 배포 시점에 설정을 변경할 수 있도록 볼륨 권한을 조정합니다.

**📂 `docker-compose.yml` (Main)**

```yaml
version: '3.8'

services:
  main-nginx:
    image: nginx:latest
    container_name: main-nginx
    restart: always
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf
      - /etc/letsencrypt:/etc/letsencrypt
      - ./conf.d:/etc/nginx/conf.d  # [중요] Jenkins가 service-url 파일을 수정해야 함
    extra_hosts:
      - "host.docker.internal:host-gateway"
    networks:
      - app-network
      - dev-net
      - prod-net

  jenkins:
    image: jenkins/jenkins:lts
    container_name: jenkins
    restart: always
    ports:
      - "8333:8080"
    volumes:
      - ./jenkins_home:/var/jenkins_home
      - /var/run/docker.sock:/var/run/docker.sock
      - /usr/bin/docker:/usr/bin/docker
    environment:
      - JENKINS_OPTS="--prefix=/jenkins"
      - TZ=Asia/Seoul
    networks:
      - app-network
      - dev-net
      - prod-net

  portainer:
    image: portainer/portainer-ce:latest
    container_name: portainer
    restart: always
    ports:
      - "8000:9000"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      - portainer_data:/data
    networks:
      - app-network

networks:
  app-network:
    external: true
  dev-net:
    external: true
  prod-net:
    external: true

volumes:
  portainer_data:
    external: false
```

**📂 `nginx.conf` (동적 라우팅 설정)**

Nginx 설정 내에서 `include` 지시어와 변수(`$service_url`)를 사용하여, Nginx 재시작 없이 트래픽을 Blue/Green 컨테이너로 전환합니다.

```nginx
events {
    worker_connections 1024;
}

http {
    resolver 127.0.0.11 valid=5s;

    server {
        listen 80;
        server_name i14e104.p.ssafy.io;
        return 301 https://$host$request_uri;
    }

    server {
        listen 443 ssl;
        server_name i14e104.p.ssafy.io;

        ssl_certificate /etc/letsencrypt/live/i14e104.p.ssafy.io/fullchain.pem;
        ssl_certificate_key /etc/letsencrypt/live/i14e104.p.ssafy.io/privkey.pem;

        # [Prod] 프론트엔드
        location / {
            proxy_pass http://prod-frontend:80;
            # (Header 설정 생략)
        }

        # [Prod] 백엔드 API (Blue/Green)
        location /prod-api/ {
            # Jenkins가 배포 시점에 이 파일 내용을 수정함 (예: set $service_url http://prod-backend-green:8080;)
            include /etc/nginx/conf.d/service-url-prod.inc;
            
            rewrite ^/prod-api/(.*)$ /$1 break;
            proxy_pass $service_url;  # 위 파일에서 정의된 주소로 프록시
            
            proxy_cookie_path / "/; SameSite=None; Secure";
        }

        # [Dev] 프론트엔드
        location /dev/ {
            proxy_pass http://dev-frontend:80;
        }

        # [Dev] 백엔드 API (Blue/Green)
        location /dev-api/ {
            include /etc/nginx/conf.d/service-url-dev.inc;
            
            rewrite ^/dev-api/(.*)$ /$1 break;
            proxy_pass $service_url;
            
            proxy_cookie_path / "/; SameSite=None; Secure";
        }

        # [Management] Jenkins & Portainer
        location /jenkins {
            proxy_pass http://jenkins:8080;
            # (Header 설정 생략)
        }
        location /portainer/ {
            proxy_pass http://portainer:9000/;
            # (Header 설정 생략)
        }    
    }
}
```

```yaml
        image: openvidu/openvidu-coturn:2.25.0
```

### 3.7. AI 채팅 서비스 (ai-chat, Spring WebFlux)

싱글 모드(AI 수덕과 1:1 한국어 채팅 → 쉐도잉 문장 생성)의 AI 채팅 API를 별도 WebFlux 서비스로 분리했습니다. 기존 `backend/`에도 같은 API 계약의 구현이 남아 있으며, 성능 비교의 기준선으로 사용합니다(3.8 참고).

- **역할:** `/api/v1/ai-chat/*` 처리 (세션 생성, 인사말·메시지 SSE 스트리밍, 대화 기록 조회, 쉐도잉 문장 생성)
- **소스:** `ai-chat/` (Spring Boot WebFlux, Java 17, Gradle)
- **포트:** `8081` (컨테이너 내부)
- **의존성:** Redis (backend와 같은 인스턴스·같은 키 사용), OpenAI API
- **인증:** backend가 발급한 JWT를 같은 비밀키로 검증 (별도 로그인 API 없음)
- **배포 상태:** EC2 미배포. 아래 Docker·Nginx 설정은 **예시**입니다.

> Dev Backend(Blue)가 호스트 포트 `8081`을 쓰고 있으므로(3.2 참고), ai-chat은 호스트 포트를 열지 않고 Docker 네트워크 안에서 컨테이너 이름으로 접근합니다.

**1) 환경변수**

| **변수** | **기본값** | **설명** |
| --- | --- | --- |
| `REDIS_HOST` | `localhost` | Redis 호스트 (운영 예: `prod-redis`) |
| `REDIS_PORT` | `6379` | Redis 포트 |
| `OPENAI_BASE_URL` | `https://api.openai.com` | OpenAI 주소 (부하 테스트에서는 mock 주소) |
| `OPENAI_API_KEY` | (없음) | OpenAI API 키 |
| `OPENAI_MODEL` | `gpt-4o-mini` | 사용 모델 |
| `JWT_SECRET` | (없음, 필수) | backend의 `jwt.secret`과 **같은 값**이어야 토큰이 통함 |

- 설정 파일: `ai-chat/src/main/resources/application.yml`
- 로컬에서는 `ai-chat/.env`(gitignore)를 읽고, Docker에서는 환경변수로 넘깁니다.

**2) 로컬 실행**

```bash
# Redis(localhost:6379)와 backend(8080)가 떠 있어야 함
cd ai-chat
cp .env.example .env        # OPENAI_API_KEY, JWT_SECRET 채우기
bash ./gradlew bootRun      # http://localhost:8081
```

- `.env`는 작업 디렉터리 기준으로 읽으므로 반드시 `ai-chat/`에서 실행합니다.
- 프론트 개발 서버에서 AI 채팅만 ai-chat으로 보내려면 `AI_CHAT_PORT=8081`을 주고 띄웁니다. 지정하지 않으면 `8080`(backend)으로 갑니다.

```bash
cd frontend
AI_CHAT_PORT=8081 npm run dev
```

- 카카오 로그인 없이 확인할 때는 개발 서버의 `/dev-login` 페이지로 테스트 계정 로그인을 합니다 (backend의 `test-signup`/`test-login` 사용, 개발 모드 전용).

**3) Docker 빌드 / 실행 (예시)**

```bash
# 빌드 (멀티 스테이지: eclipse-temurin:17-jdk → 17-jre)
docker build -t sudaduck-ai-chat ./ai-chat

# 실행 (prod-net 예시. 호스트 포트는 열지 않음)
docker run -d --name prod-ai-chat \
  --network prod-net \
  --restart always \
  -e REDIS_HOST=prod-redis \
  -e REDIS_PORT=6379 \
  -e OPENAI_API_KEY=[OPENAI_API_KEY] \
  -e OPENAI_MODEL=gpt-4o-mini \
  -e JWT_SECRET=[JWT_SECRET] \
  -e TZ=Asia/Seoul \
  sudaduck-ai-chat
```

**4) Nginx 분기 (예시)**

`/api/v1/ai-chat/` 요청만 ai-chat(8081)으로 보내고 나머지는 기존처럼 backend로 보냅니다. 3.4의 `nginx.conf` `server` 블록에 추가하며, `/prod-api/`보다 긴 경로라서 이 location이 먼저 선택됩니다.

```nginx
# [Prod] AI 채팅 → ai-chat (WebFlux)
location /prod-api/api/v1/ai-chat/ {
    rewrite ^/prod-api/(.*)$ /$1 break;
    proxy_pass http://prod-ai-chat:8081;

    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

    # [필수] SSE 스트리밍
    proxy_buffering off;       # 끄지 않으면 Nginx가 토큰을 모아 두었다가 한 번에 보냄
    proxy_read_timeout 60s;    # ai-chat 스트림 상한(stream-timeout 60s)과 맞춤
}
```

- Dev 환경은 `/dev-api/api/v1/ai-chat/`, `dev-ai-chat:8081`로 같은 형태입니다.
- API prefix 없이 서비스하는 경우 `location /api/v1/ai-chat/`로 두고 `rewrite`를 뺍니다.

### 3.8. 성능 측정 환경 (bench)

기존 방식(backend, Tomcat)과 ai-chat(WebFlux)의 AI 채팅을 같은 자원(컨테이너당 2 vCPU / 1.5GB)과 같은 k6 시나리오로 비교하는 로컬 측정 환경입니다. OpenAI는 실측 지연값을 고정한 mock(`bench/mock-gpt`)으로 대체하고, Prometheus·Grafana로 서버 지표를 수집합니다. 운영 배포와는 무관하며, 측정 방법·결과·해석은 [bench/README.md](../bench/README.md)에 정리했습니다.

```bash
cd bench
cp .env.example .env              # JWT_SECRET 채우기
```

## 메인 화면 설명

<img src="assets/image%205.png" width="500" alt="메인 화면 페이지">

[메인 화면 페이지]

메인 화면에서는 사용자가 학습 방식을 선택할 수 있습니다. 

현재는 **연습 모드**와 **함께하기 모드** 두 가지가 제공됩니다. **연습 모드**는 AI와 1:1로 대화 또는 혼자 말하며 영어 연습을 할 수 있는 기능이지만, 본 테스트 시점에서는 **오픈 예정 상태로 접속이 불가능**합니다.

**함께하기 모드**는 친구들과 방을 생성하거나 참여하여 실제 대화를 통해 영어 학습을 진행하는 주요 기능입니다. 본 유저 테스트에서는 **함께하기 모드를 중심으로 테스트를 진행**합니다.

1. 사용자는 로그인 후 대기방 화면에서 **`방 만들기`** 버튼을 클릭합니다.
2. 방 생성 화면에서 방 정보를 입력합니다.
3. 대화 주제는 **필요한 경우 `AI 주제 추천` 기능을 활용할 수 있습니다.**

2. 방이 정상적으로 생성되며, 방 코드가 발급됩니다.
3. 방장은 참여 코드를 복사해 참여자에게 전달합니다.

방장이 설정한 **모든 턴이 종료되면**, 자동으로 **복습 미니게임 단계로 이동**하여 학습한 내용을 다시 한 번 복습할 수 있습니다.

<img src="assets/%EC%8A%A4%ED%81%AC%EB%A6%B0%EC%83%B7_2026-02-06_120550.png" width="500" alt="문제 풀기 페이지">

문제는 **앞선 턴에서 학습한 영어 문장**을 기반으로 빈칸 채우기 형태로 출제됩니다.

<img src="assets/%EC%8A%A4%ED%81%AC%EB%A6%B0%EC%83%B7_2026-02-06_120609.png" width="500" alt="게임 결과 페이지">

[전체 리뷰 확인 페이지]

복습 미니게임이 종료되면 **게임 결과**를 통해 각 참여자의 점수를 확인할 수 있습니다.

**전체 리뷰**를 선택하면 내가 틀린 문장과 정답, 리뷰 내용을 확인할 수 있습니다.

이때 **1등 참여자는 코인 보상**을 획득하며, 획득한 코인은 **마이페이지에서 캐릭터 및 AI 오리 커스터마이징**에 사용할 수 있습니다.

게임 종료 후에는 **다시 대기방으로 이동**하거나 **방을 나가기** 중 하나를 선택할 수 있습니다.

또한 게임이 종료되면, **마이크가 다시 활성화되어** 참여자 간 자유로운 대화가 가능합니다.
